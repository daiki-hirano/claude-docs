# 品質チェック

エージェントが該当ファイルを直接確認し、品質の基準を満たしているかを報告する。**チェックと報告のみを行い、ファイルの修正はしない**（修正は報告後に作業者が依頼した場合のみ行う）。

## チェック対象

- 基本は書き出されたファイル、`public_html` 配下を対象にする。
  - 書き出し先は `_develop/package.json` の `config.dest`（+ `config.subDirectory`）。アセットは `config.assetPath`（`assets`）配下。
  - 対象ページは `public_html` 配下の全 `.html`（`assets/` 配下は除く）。
- 以下の場合は `_develop/src` 配下のファイルも確認する。
  - 条件を満たしていない項目があり、原因や修正箇所（どの Pug・CSS・TS か）を特定する必要がある場合
  - ビルド結果だけでは判断できない場合（例: 元画像が jpg / png か、どのデータから出力されているか）
- `_develop/src/pug/utils/_base.pug` の `isSSI` が `true` の場合、header / footer は `assets/include/*.html` から SSI で読み込まれる。リンク・画像・見出し・アナリティクスのチェックではこれらのファイルも含めて確認する。
- `public_html` が古い・存在しない可能性がある場合は、チェック前に作業者へビルド（`_develop` で `npm run build:all`）が必要か確認する。

## チェック条件（案件ごとの設定）

案件によって要否が変わる項目は、作業者に質問して決め、条件ファイルに保存する。2回目以降は保存した条件を使う。

### 条件の項目

| 項目           | 質問内容                                    | 使う項目   |
| -------------- | ------------------------------------------- | ---------- |
| WebP           | WebP 変換が必要か                           | 1          |
| 本番ドメイン   | 決まっているか（決まっていればドメイン）    | 5・6・7・9 |
| sitemap.xml    | 要望があるか                                | 7          |
| llms.txt       | 要望があるか                                | 9          |
| アナリティクス | 指定されたツール（GA4 / GTM など）と測定 ID | 11         |

### 条件ファイル

- 保存先はリポジトリのルートの `.agents/quality-check-conditions.md`。どのエージェントからも読めるようにし、作業者間で共有するためコミットする。
- スキルのディレクトリ内には保存しない（スキルを他のプロジェクトへコピーしたときに、条件が持ち込まれないようにするため）。
- 形式は以下のとおり。

```markdown
# 品質チェックの条件

最終更新: YYYY-MM-DD

| 項目           | 条件     |
| -------------- | -------- |
| WebP           | 必要     |
| 本番ドメイン   | 未定     |
| sitemap.xml    | 要望なし |
| llms.txt       | 要望なし |
| アナリティクス | 指定なし |
```

### 進め方

1. 条件ファイルがあるか確認する。
2. **ない場合（初回）**: 「条件の項目」をすべて作業者に質問する。質問ツール（AskUserQuestion など）が使える場合はそれを使い、使えない場合はチャットでまとめて質問する。回答を条件ファイルに保存してからチェックを始める。
3. **ある場合（2回目以降）**: 保存されている条件を表で示し、「前回の条件のままでよいか」を作業者に確認する。
   - そのままでよい場合は、その条件でチェックする。
   - 変更がある場合は、変更する項目だけ聞き直し、条件ファイルを更新してからチェックする。
   - 条件ファイルにない項目（スキルに項目が追加された場合など）は、その項目だけ質問して追記する。
4. 依頼文に条件が書かれている場合は、その条件を使い、条件ファイルも更新する（質問・確認は省略してよい）。
5. 回答が「不明」の場合は「要望なし」「指定なし」「未定」として扱い、条件ファイルにもそのように保存する。

報告の概要には、使った条件を必ず記載する。

## チェック項目

判定は ❌ エラー（基準を満たしていない）/ ⚠️ 警告（要確認）/ ✅ OK / － 対象外 の4段階で行う。

### 本番ドメインの扱い（項目5・6・7・9 共通）

- 対象: canonical、`og:url`、`og:image`、構造化データ（JSON-LD）内の URL、sitemap.xml の `loc`、llms.txt のリンク
- **本番ドメインが決まっている場合**（チェック条件）: 対象の URL が指定されたドメインの絶対 URL でなければ ❌（ドメインが空・仮のドメイン・別のドメインを含む）。
- **本番ドメインが未定の場合**: 厳密に判定せず、以下はドメイン未定義として ⚠️ にする（❌ にはしない）。
  - ドメイン部分が空（パスのみの URL、`https:///`、`//` から始まる URL など）
  - 仮のドメイン（`example.com` / `example.jp` などの `example.*`、`localhost`、`127.0.0.1`、`test` / `dummy` / `sample` を含むドメイン、`.local` / `.test` など）

### 1. 画像の WebP 変換

- WebP が不要な案件（チェック条件）は － 対象外 とし、参照している画像ファイルが存在するかだけ確認する。
- WebP が必要な場合は、以下を確認する。
  - `_develop/package.json` の `config.enableWebP` が `true` か。`false` なら ❌。
  - `_develop/src/images` 配下の jpg / png それぞれに対応する WebP が `public_html/assets/images_min/` 配下に生成されているか。なければ ❌。
  - HTML 内の `img` / `source` が jpg / png を参照している場合、同じ `picture` 内に `type="image/webp"` の `source` があるか。なければ ❌。
  - CSS（`public_html/assets/css/`）の `url()` で jpg / png を参照していれば ⚠️。
- 参照している画像ファイルが存在しなければ ❌（WebP の要否にかかわらず確認する）。

### 2. 画像の alt

- 全 `img` に `alt` 属性があるか。属性自体がなければ ❌。
- 装飾目的以外の画像に alt テキストが入っているか。
- `alt=""` の画像は一覧にし、ファイル名・class・周囲の要素から装飾目的として妥当か判断する。意味のある画像（写真、図、テキストを含む画像など）と思われるものは ⚠️。

### 3. title / description（全ページの内容を表示）

- 全ページの `title` と `meta name="description"` を確認する（`name` の大文字小文字は区別しない）。
- タグがない・中身が空なら ❌。
- 他のページと重複している場合は ⚠️（重複しているページ名も記載）。
- 正しいテキストかを作業者が確認できるよう、**問題の有無にかかわらず全ページの内容を表で表示する**。

### 4. 見出しの階層構造

- 各ページの `h1`〜`h6` を出現順に確認する（SVG 内の `title` などは対象外）。
- `h1` がない → ❌、`h1` が複数 → ⚠️。
- 見出しレベルが飛んでいる（例: `h2` → `h4`）→ ❌。
- 最初の見出しが `h1` 以外 → ⚠️、中身が空の見出し → ⚠️（画像のみの見出しは alt をテキストとみなす）。
- 問題のあったページは見出し構造をツリーで表示する。

### 5. canonical

- 全ページに `link rel="canonical"` があるか。タグ自体がなければ ❌。
- `href` が空、またはドメインが未定義・仮のドメインの場合は ⚠️（「本番ドメインの扱い」参照）。
- URL のパスがページの場所と一致しているか（例: `public_html/about/index.html` → `/about/`）。不一致は ⚠️。
- ドメインが全ページで統一されているか、他のページと重複していないか。問題があれば ⚠️。
- 404 ページは canonical がなくてもよい。ある場合は、クエリ（`?v=` などのキャッシュ対策）や不要な文字列が付いていないかだけ確認し、付いていれば ⚠️。`og:url` も同じ扱いにする。

### 6. OGP（全ページの内容を表示）

- 全ページに `og:url` / `og:title` / `og:description` / `og:image` / `og:type` / `og:site_name` が設定されているか。タグがない・`og:title` などテキスト系の中身が空は ❌（404 ページの `og:url` は項目5と同じ扱い）。
- `og:url` / `og:image` の URL が空、またはドメインが未定義・仮のドメインの場合は ⚠️（「本番ドメインの扱い」参照）。
- `og:url` のパスが canonical と一致しているか。不一致は ❌。
- `og:image` がサイト内の画像なら `public_html` に存在するか（なければ ⚠️）。
- `og:title` / `og:description` の重複、`og:site_name` がページによって異なる場合は ⚠️。
- **問題の有無にかかわらず全ページの内容を表示する**。

### 7. sitemap.xml

- 要望がなくても、なるべく作成する。
  - 要望がある場合: `public_html/sitemap.xml` がなければ ❌。
  - 要望がない場合: なければ ⚠️（作成を推奨する旨を報告）。
- ある場合は中身を確認する。
  - XML 宣言があり、ルートが `urlset`（`xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"`）または `sitemapindex` か。
  - 各 `url` に `loc` があり、エスケープされていない `&` がないか。
  - `loc` のドメインが未定義・仮のドメインの場合は ⚠️（「本番ドメインの扱い」参照）。
  - `loc` が実在するページを指しているか、各ページの canonical と一致しているか。
  - noindex のページ・404 ページが含まれていないか、逆に含まれていないページがないか。
  - `lastmod` がある場合は W3C 形式（`YYYY-MM-DD` など）か。
  - 存在しないページや形式の誤りは ❌、重複・過不足は ⚠️。

### 8. 404 ページ

- `public_html/404.html` があるか。なければ ❌。noindex が設定されていなければ ⚠️。
- Chrome DevTools MCP が接続されている場合は、表示を確認する（ローカルサーバーの準備は「Chrome DevTools MCP での確認」参照）。
  1. `/404.html` を開き、レイアウト崩れ・画像切れ・コンソールエラーがないかをスクリーンショットとコンソールで確認する。
  2. 存在しない URL（例: `/not-found-check/`）を開き、何が表示されるかを記録する。BrowserSync は存在しない URL で 404.html を返さないため、ここで 404.html が出なくてもエラーにはしない。本番の表示はサーバー設定（`.htaccess` の `ErrorDocument 404` など）に依存する旨を報告する。
- **Chrome DevTools MCP が接続されていない場合は、表示確認を実施できなかったことを必ず報告する。**

### 9. llms.txt（要望がある場合のみ）

- 要望がない場合はチェックせず － 対象外 とする。ただし `public_html/llms.txt` がある場合は、以下の内容チェックを行う。
- 要望がある場合、`public_html/llms.txt` がなければ ❌、空なら ❌。
- 1行目が `# サイト名` の H1 か（llms.txt の仕様で必須）。違えば ⚠️。
- 記載されているサイト内リンクの先が存在するか。存在しなければ ⚠️。リンクのドメインが未定義・仮のドメインの場合も ⚠️。

### 10. リンク（href）

- 全ページ（SSI の include を含む）の `a` タグを確認する。
- `href="#"`・`href=""`・`javascript:` で始まるダミーリンクは ❌（リンクテキストも記載）。
- `href` のない `a` タグは ⚠️。
- アンカー（`#id`）は対象外とするが、ページ内に該当する `id` がなければ ⚠️（`#top` は除く）。
- サイト内リンクの先が `public_html` に存在しない場合は ⚠️。

### 11. アナリティクス（GA4 / GTM など）

案件ごとに使うツールが違い、測定 ID が準備前のこともあるため、この項目はすべて ⚠️ で判定する（❌ にはしない）。

- 全ページ（SSI の include を含む）で、以下のタグが入っているかを確認する。
  - GA4: `googletagmanager.com/gtag/js?id=G-` の読み込みと `gtag('config', 'G-...')`
  - GTM: `googletagmanager.com/gtm.js?id=GTM-` の head 内スクリプトと、body 直後の `noscript`（`ns.html?id=GTM-`）
  - その他のツールが指定されている場合はそのタグ
- 以下は ⚠️。
  - どのアナリティクスも入っていない（指定されたツールがある場合は、そのツールが入っていない）
  - 指定された測定 ID と異なる、または仮の ID（`G-XXXXXXXXXX`、`GTM-XXXXXXX` など）
  - 一部のページにだけ入っていない、ページによって ID が異なる
  - GTM の head スクリプトと `noscript` のどちらかが欠けている
  - GA4 の直接設置と GTM 経由の GA4 が両方あり、二重計測の可能性がある（GTM の中身はファイルから確認できないため、可能性として報告する）
- 確認したツールと ID をページごとに一覧で表示する（全ページ同じ場合はまとめて記載してよい）。

### 12. コンソールエラー

- Chrome DevTools MCP が接続されている場合に、全ページで確認する（ローカルサーバーの準備は「Chrome DevTools MCP での確認」参照）。
  1. 各ページを開き、ページ下部までスクロールしてから（スクロールで動く処理も実行させるため）コンソールメッセージを取得する。
  2. PC・SP それぞれのデザイン幅で確認する（幅によって実行される JS が変わる場合があるため）。
  3. `error` レベルのメッセージ（JS の例外、読み込みに失敗したリソースなど）は ❌。
- エラーが発生している場合は、以下を記載する。
  - 発生しているページと幅（PC / SP）
  - エラーメッセージ
  - 発生している JS ファイルと行番号（例: `public_html/assets/js/main.js:120`）
  - 該当するソースコード（`_develop/src/js` 配下の TS ファイルと該当箇所。特定できなかった場合はビルド後のファイルの該当箇所を引用する）
- **Chrome DevTools MCP が接続されていない場合は、確認を実施できなかったことを必ず報告する。**

## Chrome DevTools MCP での確認

項目8・12 で使う。

- ローカルサーバー（BrowserSync）の URL を確認する。ポートはデフォルト 3000 だが起動時に変わる可能性があるため、起動ログの URL を使う。起動していなければ作業者に確認する。

## 報告フォーマット

チャットで以下の形式で報告する。

1. **概要**: 対象ディレクトリ、ページ数、サイトのドメイン（canonical から判定。未定義・仮のドメインの場合はその旨）、使ったチェック条件（前回の条件を使ったか、変更したか）
2. **サマリー**: 項目ごとのエラー数・警告数の表（対象外の項目は「対象外」と記載）
3. **各項目の結果**: 上記 1〜12 の順に、❌ → ⚠️ の順で列挙する。該当ページ・ファイルを必ず記載し、原因を `_develop/src` で特定できた場合は修正箇所（例: `_develop/src/pug/about/index.pug`）も記載する。問題がなければ ✅。
4. **全ページの title / description の表**（項目3）と **全ページの OGP の表**（項目6）は省略せずに表示する。
5. **未実施の項目**: Chrome DevTools MCP 未接続などで確認できなかった項目と理由

```markdown
## サマリー

| 項目                | エラー | 警告   |
| ------------------- | ------ | ------ |
| 1. 画像の WebP 変換 | 0      | 1      |
| ...                 |        |        |
| 9. llms.txt         | 対象外 | 対象外 |

- ❌ `/about/`（SP）`TypeError: Cannot read properties of null (reading 'addEventListener')`
  - 発生箇所: `public_html/assets/js/main.js:120`
```
